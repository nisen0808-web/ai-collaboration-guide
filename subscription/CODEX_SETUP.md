# Codex 首次配置指南

本指南供使用者交给自己的 Codex，让它协助配置本机 Claude 与 Grok 协作。这里提供的是开发候选，连接成功与否取决于本机环境、账号权限和官方客户端版本。仓库链接本身不会安装软件、完成登录，或保证每个新聊天都会调用两家。

订阅客户端方案调用使用者自行安装和登录的官方客户端，不要求使用者向 Codex 提供 API 密钥。根目录另有独立的 API 示例；除非使用者明确选择，不要改用该示例。使用前请阅读[客户端说明](README.md)，并遵守各供应商当前的服务条款。

## 交给 Codex 的任务

如果使用者只提供了仓库链接，请先确认本机的操作系统、可用工具和权限，再按照下面的顺序协助。使用者对当前任务的明确要求优先于本指南。不可向协作者发送登录资料、完整聊天记录、无关私人文件或未获授权的任务内容。

### 1. 准备稳定的源码目录

1. 先检查是否已经有本工具、相同 MCP 服务或相关工作正在运行。保留现有服务、账本、任务和用户配置；不要因为一次安装而重启、停止、覆盖或清理它们。
2. 从使用者提供的仓库链接获取完整源码，并确认检出的地址和版本。选择用户同意的、可长期保留的目录。服务注册会引用该目录下的文件；删除或移动目录后连接可能失效。
3. 如果已有的检出目录可能正被服务使用，不要原地更新它；选择独立目录，并先核对是否已有服务指向其他版本。不要盲目重复注册。
4. 本指南及以下命令位于仓库的 `subscription` 目录。检查 Python 3.10 或更新版本、Codex 命令行以及官方 Claude Code 和 Grok Build 客户端是否可用；缺少时按官方文档协助使用者准备，不要下载不明来源的程序。Claude Code 还需支持 `--permission-prompts`。现有客户端不在系统路径时，可按客户端说明显式指定路径。

可在 `subscription` 目录运行 `python -B ai_team.py setup-check` 做初查。它只报告客户端是否能找到、用户级规则文件是否存在，不改变用户配置、不启动登录或供应商任务，也不证明登录、MCP 连接或规则已经生效。退出码为 0 只表示检查完成；有无缺项必须读取输出字段。规则文件“存在”也不代表其非空或已生效，选择合并位置前仍需实际检查。`-B` 防止此检查写入 Python 字节码缓存；它不删除或禁止读取已有缓存。对非默认客户端路径，可使用 `--claude-cli`、`--grok-cli`、`--codex-cli` 参数。

### 2. 让使用者本人登录

默认登录使用工具自己的独立配置，不会自动复用已有客户端登录；如果使用者明确选择已有配置，可按[客户端说明](README.md)指定配置路径。先确认是否存在共享配置或在途任务，不擅自修改它们。

请使用者在**本人控制且不会把终端输入输出回传给 Codex 或聊天记录的交互终端**中，进入仓库 `subscription` 目录，分别运行：

```text
python ai_team.py login claude
python ai_team.py login grok
```

这两个命令启动未修改官方客户端的登录流程。让使用者自行处理浏览器和终端中的官方提示；不要要求其发送密码、验证码、授权链接、令牌或截图。完成后只需告知 Codex 哪个登录已完成。如果命令找不到客户端，先协助检查官方客户端及其路径；不要声称已经登录。

以上是全部使用默认路径的例子。如果使用者选择 `--data-dir`、`--claude-profile`、`--grok-profile`、`--claude-cli` 或 `--grok-cli`，应在对应的 `login` 和后续 `install` 中保持同一组实际值，并使用绝对路径：相对路径在不同工作目录中可能指向不同位置。例如先用 `login claude --data-dir <选定目录> --claude-profile <选定配置>` 登录，就必须在安装时传入同样的 `--data-dir` 和 `--claude-profile`；Grok 及客户端路径同理。占位符需要替换为使用者自己的值。不要为了统一路径复制登录文件或令牌。

当前方案以登录终端和 Codex 使用同一个系统账户为前提，不支持将一个账户的私有配置直接共享给另一个系统账户。即便是同一账户，不同会话的环境变量也可能使默认数据目录不同。请使用者在自己控制的终端核对两边实际使用的数据目录是否一致，只需向 Codex 告知核对结果；不一致时，在同一账户下选用同一个绝对数据目录，并在登录和安装时明确指定。若需要 Codex 协助读取本机路径，工具输出可能进入当前会话；不要将路径、账户信息或凭据发布到仓库或发送给其他协作者。权限不足时停止并说明，不绕过系统限制。

不要为了继续自动切换 API 密钥、收费接口或其他账号。订阅和可用模型由各自官方账号决定；登录成功也不能证明额度、模型或真实任务可用。

### 3. 选择模型并接入 Codex

1. 协助使用者查看两家账号实际支持的模型及客户端选项，让其自行选择模型和思考强度；不要套用仓库作者的偏好，也不要把默认值当成所有账号都支持。可让使用者在本人终端参考官方客户端与文档选择；选择本身不证明实际模型可用。如果由 Codex 查询 Grok，须在隔离子进程中复用 `grok/grok_adapter.py` 的 `_env()` 所有环境规则：使用登录时的 Grok profile（默认是数据目录下的 `grok-profile`）、隔离 HOME 和临时目录及适配器的各项开关，不能仅设置 `GROK_HOME`；还须另外设置隔离工作目录。不继承 API 密钥变量，不修改用户全局环境或打印环境变量和凭据；代理设置也可能包含敏感信息。无法可靠复用该环境时，不要自动运行手工拼装的查询，应如实说明模型可用性尚未验证。[客户端说明](README.md)给出了客户端选项。
2. 先检查 Codex 是否已经注册此工具，以及是否有相关在途任务。全部使用默认目录和客户端路径时，首次安装可在 `subscription` 目录运行 `python ai_team.py install --grok-model <本人可用的模型名>`。**不要在自定义登录之后直接照抄此默认示例**：例如登录时选择了自定义数据目录，就应运行 `python ai_team.py install --data-dir "<与两次登录一致的绝对目录>" --grok-model "<本人可用的模型名>"`。如果登录时还自定义了 profile 或客户端路径，在同一条安装命令中逐项传入所有自定义参数：`--claude-profile`、`--claude-cli` 分别沿用 Claude 登录时对应的绝对路径，`--grok-profile`、`--grok-cli` 分别沿用 Grok 登录时对应的绝对路径；两家的路径各自确定，不必相同。未自定义的参数可省略。按使用者选择提供其他模型和强度。不要把尖括号占位文字当作真实值。[客户端说明](README.md)列出可配置参数。
3. 安装会先核对模型名和思考强度的格式（Claude 强度为 `low`、`medium`、`high`、`xhigh`、`max`，Grok 没有 `max`），不合格时不写任何标记、不调用 Codex；格式合格不代表账号可用。随后只读检查已注册的服务；发现名称为 `ai_team` 或以 `ai_team_` 开头的旧服务、或检查不明时会停止，不删除或覆盖已有服务，此时也不留下标记，处理好原因后可以直接再试。改名后的旧服务不能仅凭名称识别，仍须在安装前检查。检查通过后才在 Codex 配置目录记录一次尝试，标记为其中的 `.ai-collaboration-guide-install-attempt`，以及数据目录中的 `codex-install-attempt.txt`；它们都不证明安装成功，之后的步骤失败或中断时标记会保留。启动安装时使用可短暂返回控制权的命令会话；如果等待过久，保留原会话并继续其他可行工作，之后读取原会话的完成结果，不强行终止或另起一次安装。若失败、中断或会话结果不明，先检查 Codex 已注册的服务与原安装会话，再与使用者核对如何处理这些标记；不要自动删除标记、重复安装、覆盖现有 MCP 服务或更换账本。配置目录级保护约束本版本在同一 Codex 配置目录下的尝试，不阻止其他程序同时修改配置，也不代表所有不同的配置目录互相可见。
4. 按 Codex 提示加载新连接。必要时指导使用者在其他在途工作安全结束后重载；不要强行结束进程，也不要宣称已经运行的聊天自动加载了新配置。MCP 连接和登录就绪只是准备状态。

### 4. 准备验证

准备一道不含私人信息的简短测试。先完成下方规则设置，再通过新聊天向两家各发送一次，避免重复测试。两家使用不同的唯一请求标识，首次独立判断时不互相提供对方答案。分别读取同一个请求的实际结果并报告：是否完成、答案是否正确、模型和思考强度有哪些可核对的证据。不要把模拟测试、登录状态、排队或模型自报当成真实成功。

一方不可用、忙碌或较慢时，继续可完成的工作，明确说明缺少哪一方及影响。提交失败、超时或状态不明确时只查询原任务，不自动重发、换键重投或切换付费接口。Grok 若因技能或扩展预检停止，请按[客户端说明](README.md)报告实际原因；不要擅自禁用共享配置的技能。只有用户明确选择并确认独占配置后，才可针对该配置处理。

### 5. 设置后续聊天的协作偏好

与使用者确认偏好适用范围：仅当前项目，还是本机新项目和新聊天。可参考[通用协作规则模板](CODEX_GLOBAL_RULES.md)，在适当的 Codex 指令文件中安全合并使用者选择的规则；先检查已有规则和覆盖文件，保留原内容，不重复追加，不导入本仓库作者的个人要求。修改使用者级配置前，说明影响和回退方法；发生冲突或无法安全合并时停下该步骤并告知使用者。

本机全局规则位于 `CODEX_HOME`（未指定时默认 `~/.codex`）。先检查该目录中 `AGENTS.override.md` 和 `AGENTS.md`：非空的 override 在同层优先；不得通过新建 override 遮蔽已有规则。若选择全局范围，在实际生效的文件中仅合并模板的标记区块，并保留原有内容；已有区块应核对后更新，不能重复追加。对链接、权限、同时修改或大小限制不能安全处理时停止并说明；回退只移除本工具的标记区块，不删除其他内容。项目级规则可覆盖全局规则。[Codex 指令文件说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

随后启动一个**新的** Codex 聊天，检查该入口实际读取的规则和 MCP 工具，再按使用者授权向两家各提交步骤 4 准备的测试一次并核对实际结果。规则写入或服务安装不证明新聊天已经读取，也不保证云端、手机或另一台电脑有本机连接。项目指令、工具权限和使用者对当前任务的明确要求仍可能改变是否调用；不能承诺每次一定自动执行。

完成时分别报告：客户端是否安装、本人登录是否完成、MCP 是否接通、两家是否实际返回结果、规则设置到哪里，以及未完成和未验证的事项。不要公开本机路径、账号标识、凭据或任务内容；本机状态和客户端会话可能保留敏感信息，应保管好并避免上传。
