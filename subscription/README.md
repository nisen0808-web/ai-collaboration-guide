# 本机 AI 协作（开发候选）

让主控 AI 先处理任务，再分别邀请使用者自己的 Claude 和 Grok 协作，并检查各自结果。每个人使用自己的官方客户端和账号；程序不要求使用者生成或向主控提供 API 密钥。

**当前是开发候选，跨平台及异常恢复尚未完成验收，请勿当成正式发布版使用。** 已分别用官方客户端完成一次 Claude 和 Grok 简短真实任务，两次结果正确。Claude 的实际模型和强度缺少可核验记录；Grok 这次结果的模型和强度经额外读取官方会话记录核验，但本工具自身尚未实现自动核验。其他测试包括模拟客户端，不能把模拟通过当成真实连接成功，也不能将单次任务结果推广到所有环境。

一次 Windows 本机联调中，两家分别收到“请只输出整数 42”，均返回 `42`。该 Grok 会话的官方摘要记录 `grok-4.7` 和 `xhigh`，用量记录的 `primaryModelId` 为 `grok-4.7-build`；主控另外读取并核对了这份会话记录，本工具的结果仍标记质量未验证。这些样本执行后代码修复了损坏任务记录的状态判断，当前版本的该变化只经本机离线测试；该样本不证明新版已真实联调，也不证明其他账号、其他任务或其他平台均可用。

随后的 Grok 测试在预检阶段被拦截，记录显示没有发送模型请求；事后检查发现专用配置中有未明确标记禁用的随包技能。在使用者确认独占的测试配置中禁用检查发现的 22 个随包技能后，更新后的 Python 代码用不同的新题完成了一次真实 Grok 测试并返回正确答案。禁用技能是此次测试的配置条件，可能影响依赖这些技能的其他功能。主控另行核对该次官方会话摘要及用量记录，记录的模型标识包括 `grok-4.7` 和 `grok-4.7-build`，思考强度为 `xhigh`；本工具仍将质量标为未验证，检查元数据也仍有未验证项。原失败任务没有自动重发。Claude 的真实样本早于后续代码修改，不代表最新版已完成 Claude 真实联调。

## 使用方式（待真实验收）

准备 Python 3.10 或更新版本、Codex，以及官方 Claude Code 和 Grok Build 命令行客户端。由使用者自行完成各客户端的账号登录，不向聊天发送密码、验证码、令牌或 API 密钥。

也可以把此仓库交给自己的 Codex，并发送以下指令：

> 请阅读本仓库的 README，检查我的系统是否安装 Claude Code 和 Grok Build，指导我分别使用官方登录流程，随后按文档将本仓库的 MCP 服务接入 Codex。保留我现有的其他服务和任务；不要读取、索取或复制我的密钥、验证码与登录令牌。完成后用一个简单问题检验两家的实际结果，并分别报告未完成项。

先在终端进入仓库内的 `subscription` 目录，再运行：

```text
python ai_team.py login claude
python ai_team.py login grok
```

这会分别打开官方客户端的登录流程，登录信息由官方客户端保存。默认使用项目专用的本机数据目录；不会复制其他客户端已有的登录文件。如果希望使用已经登录的官方客户端配置，也可以显式设置 `--claude-profile` 或 `--grok-profile` 指向各自现有的配置目录，CLI 将自行读取其配置，不需要复制令牌。客户端未在系统路径时，可用 `--claude-cli` 或 `--grok-cli` 指定其位置。

当前 Grok 连接会检查是否加载了额外扩展或资料；只有检查结果明确表示技能已禁用时才会放行，未知状态仍可能导致停止。官方客户端在合成独立配置下会对已禁用技能返回 `disabled: true`；这次非生成检查不能证明模型运行期间的全部行为。若检查停止，主控应继续自己的工作并说明 Grok 未参与，不能把它当作完成的协作。

如果结果的 `inspection_reason` 是 `skills_present_or_unknown`，说明官方检查发现的技能没有全部明确标记为禁用；这并不证明它们已经运行。对**仅供本工具使用的独立 Grok 配置**，可由使用者或其主控依据[官方技能配置说明](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/08-skills.md)选择禁用相应技能，再用官方 `grok inspect --json` 检查是否明确返回 `disabled: true`。技能名称和路径可能属于私密信息，请勿贴到聊天或公开仓库。程序不会自动修改已有或共享配置；设置是否生效以实际官方检查为准，检查后配置仍可能发生变化。其他固定类别表示其他扩展或检查结果未知，不能一律归因于技能。原任务已失败或提交状态不明时，不自动重新发送。

当本工具明确禁用子代理时，检查报告里仅列出的官方内置代理不会单独导致停止；其他来源仍需明确处理。检查报告中的部分元数据尚不能验证，任务结果会标明这一点。

`install` 会将本服务添加到 Codex，并使用独立名称以避免覆盖现有服务；按提示重启连接后生效。也可将以下服务器命令手动添加到支持 MCP stdio 的主控客户端：

为避免反复安装产生多个服务，本工具会在自己的数据目录记录一次安装尝试；该记录不代表安装一定成功。需要重装时，请先确认 Codex 中已有的条目和在途任务，再处理本工具的安装标记。

```text
python /absolute/path/to/ai_team.py serve
```

例如，Codex 的 CLI 支持 `codex mcp add <名称> -- <服务器命令>`；桌面应用也可在 MCP 设置中添加本地服务。替换命令中的路径，并在添加后按客户端提示重启连接。[Codex MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

模型和思考强度可通过 `--claude-model`、`--grok-model`、`--claude-effort` 和 `--grok-effort` 调整；默认值只是通用起点，实际可用性以各自账号与客户端为准。两家服务的用量、订阅和可能产生的费用由使用者自己的账号管理。

安装前请用官方客户端列出当前账号可用模型，并在 `install` 命令中通过 `--grok-model` 显式选择其中一个。[官方设置示例](https://docs.x.ai/build/settings)使用 `grok-build` 作为默认名称，但一次只读检查的模型列表没有列出这个名称；这不能证明它无效，也不能证明其他账号可用相同模型。模型出现在列表中不等于已通过真实任务测试。

例如，先运行 `grok models`，确认该命令使用的官方账号和配置与本工具登录的相同，再将下面的 `可用模型名` 替换为列表中的名称并安装。官方客户端的默认配置和本工具的专用配置可能不同：

```text
python ai_team.py install --grok-model 可用模型名
```

Claude Code 需支持 `--permission-prompts`（官方说明为 2.1.259 或更新版本）；使用前请先检查版本。官方还提示未来可能调整 `-p` 的默认启动模式，届时需重新验证已登录账号的兼容性。本机已核对 Grok 1.0.52 的实际帮助中包含本工具使用的命令参数，不代表其他版本已验证。[Claude CLI 参考](https://code.claude.com/docs/en/cli-reference) · [Claude 程序化运行](https://code.claude.com/docs/en/headless) · [Grok CLI 参考](https://docs.x.ai/build/cli/reference)

服务向主控暴露任务提交、状态和结果查询接口。主控负责理解任务、独立执行、向两家分工、核实结果并向用户说明不可用或未完成的部分。一家较慢或不可用时，另一家仍应能继续。提交是否成功无法确认时不自动重投。慢任务达到等待阈值后标记为未确认，后台可继续等待原进程并回收结果；服务重启后可以按原任务查询，但进程被系统终止或结果丢失时无法保证恢复。

如果某个任务的运行状态无法确认，它可能继续占用本工具的本地并发位置；此时主控应继续能够完成的部分，并说明缺少的协作。状态接口会分别显示近期有活动迹象的任务数和不确定的占用数；未知作业目前尚无自动清理办法。

## 结果与隐私

任务文本会发送给所选供应商；只发送使用者允许分享的信息。运行产生的本机状态、客户端会话及供应商结果可能包含敏感内容，不要上传到公开仓库。请确保本机数据目录仅对合适的账户开放；目录保护依赖操作系统权限。程序不内置作者的账号、登录状态、个人目录、历史任务、写作风格或个人模型偏好。

模型和思考强度只有在供应商返回可核验的证据时才可称为已验证；否则如实显示未验证。失败、退出和重启后可能存在未确认任务，不能凭空当作成功或自动重复提交。
