# 本机 AI 协作（开发候选）

首次使用或希望让新项目默认尝试协作，请先看 [Codex 首次配置指南](CODEX_SETUP.md)。
其中包括官方登录、连接验证和经使用者选择后合并的[通用规则模板](CODEX_GLOBAL_RULES.md)。

让主控 AI 先处理任务，再分别邀请使用者自己的 Claude 和 Grok 协作，并检查各自结果。每个人使用自己的官方客户端和账号；程序不要求使用者生成或向主控提供 API 密钥。

**当前是开发候选，跨平台及异常恢复尚未完成验收，请勿当成正式发布版使用。** 当前客户端运行代码分别用官方客户端完成过 Claude 和 Grok 简短真实任务，结果正确；样本、代码版本和证据边界见[验证记录](EVIDENCE.md)。其他测试包括模拟客户端，不能把模拟通过当成真实连接成功，也不能将单次任务结果推广到所有环境。

## 使用方式（待真实验收）

准备 Python 3.10 或更新版本、Codex，以及官方 Claude Code 和 Grok Build 命令行客户端。由使用者自行完成各客户端的账号登录，不向聊天发送密码、验证码、令牌或 API 密钥。

Windows 请先运行 `python --version`，确认明确输出 Python 3.10 或更新版本；没有输出时，改用真实解释器的完整路径。在 `subscription` 目录中，PowerShell 写法为 `& "实际路径\python.exe" ai_team.py --help`，看到帮助文字后再继续。以下 `python ...` 均可作同样替换；详见[Python 入口自检](../README.md#第二步准备环境)。

当前以 Windows 和 Linux 为开发验证平台。**macOS 尚无受支持的卡槽恢复路径**：不确定任务占满并发位后，本工具不能释放；因此暂不推荐在 macOS 安装持久协作服务，不要通过删除账本来绕过。

也可以把此仓库交给自己的 Codex，并发送以下指令：

> 请阅读本仓库的 README，检查我的系统是否安装 Claude Code 和 Grok Build，指导我分别使用官方登录流程，随后按文档将本仓库的 MCP 服务接入 Codex。保留我现有的其他服务和任务；不要读取、索取或复制我的密钥、验证码与登录令牌。完成后用一个简单问题检验两家的实际结果，并分别报告未完成项。

先在终端进入仓库内的 `subscription` 目录，再运行：

```text
python ai_team.py login claude
python ai_team.py login grok
```

这会分别打开官方客户端的登录流程，登录信息由官方客户端保存。默认使用项目专用的本机数据目录；不会复制其他客户端已有的登录文件。如果希望使用已经登录的官方客户端配置，也可以显式设置 `--claude-profile` 或 `--grok-profile` 指向各自现有的配置目录，CLI 将自行读取其配置，不需要复制令牌。客户端未在系统路径时，可用 `--claude-cli` 或 `--grok-cli` 指定其位置。

当前 Grok 连接会检查是否加载了额外扩展或资料；只有检查结果明确表示技能已禁用时才会放行，未知状态仍可能导致停止。官方客户端在合成独立配置下会对已禁用技能返回 `disabled: true`；这次非生成检查不能证明模型运行期间的全部行为。若检查停止，主控应继续自己的工作并说明 Grok 未参与，不能把它当作完成的协作。

如果结果的 `inspection_reason` 是 `skills_present_or_unknown`，说明官方检查发现的技能没有全部明确标记为禁用；这并不证明它们已经运行。对**仅供本工具使用的独立 Grok 配置**，可由使用者或其主控依据[官方技能配置说明](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/08-skills.md)选择禁用相应技能，再用官方 `grok inspect --json` 检查是否明确返回 `disabled: true`。技能名称和路径可能属于私密信息，请勿贴到聊天或公开仓库。程序不会自动修改已有或共享配置；设置是否生效以实际官方检查为准，检查后配置仍可能发生变化。其他固定类别表示其他扩展或检查结果未知，不能一律归因于技能。原任务已失败或提交状态不明时，不自动重新发送。

当本工具明确禁用子代理时，检查报告里仅列出的官方内置代理不会单独导致停止；其他来源仍需明确处理。检查报告中的部分元数据尚不能验证，任务结果会标明这一点。

`install` 会将本服务添加到 Codex，并使用独立名称以避免覆盖现有服务；按提示重启连接后生效。也可将以下服务器命令手动添加到支持 MCP stdio 的主控客户端：

安装预检仅按名称识别 `ai_team` 和 `ai_team_` 前缀（不区分大小写），不会自动识别名称不同的旧协作服务，例如 `ai_collaboration` / `hub.py` 方案，也不检查全局规则是否仍指名调用旧服务。预检通过不代表没有旧服务或不会重复派发。安装前请按[配置指南第 1 步](CODEX_SETUP.md#1-准备稳定的源码目录)人工检查全部协作注册和全局 `AGENTS.md` / `AGENTS.override.md`，由使用者决定保留、停用或替换；决定及调用范围未明确前不安装，停用或替换须等使用者确认旧服务没有在途任务，再按确认的迁移步骤处理。

为避免反复安装产生多个服务，本工具会在自己的数据目录记录一次安装尝试；该记录不代表安装一定成功。需要重装时，请先确认 Codex 中已有的条目和在途任务，再处理本工具的安装标记。

```text
python /absolute/path/to/ai_team.py serve
```

例如，Codex 的 CLI 支持 `codex mcp add <名称> -- <服务器命令>`；桌面应用也可在 MCP 设置中添加本地服务。替换命令中的路径，并在添加后按客户端提示重启连接。[Codex MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

模型和思考强度可通过 `--claude-model`、`--grok-model`、`--claude-effort` 和 `--grok-effort` 调整；默认值只是通用起点，实际可用性以各自账号与客户端为准。两家服务的用量、订阅和可能产生的费用由使用者自己的账号管理。

安装前请用官方客户端列出当前账号可用模型；新安装必须在 `install` 命令中通过 `--grok-model` 显式选择其中一个。已安装连接及其他命令的默认行为不变。[官方设置示例](https://docs.x.ai/build/settings)使用 `grok-build` 作为默认名称，但一次只读检查的模型列表没有列出这个名称；这不能证明它无效，也不能证明其他账号可用相同模型。模型出现在列表中不等于已通过真实任务测试。

官方客户端的默认配置和本工具的专用配置可能不同；直接运行 `grok models` 可能使用其他配置，不能证明本工具使用的账号或模型可用；用 `python ai_team.py models grok` 则按本工具的专用配置和隔离环境查询（自定义过数据目录、profile 或客户端路径时带上相同参数）。配置引导中的[模型选择步骤](CODEX_SETUP.md#3-选择模型并接入-codex)说明如何避免混用；将下面的 `可用模型名` 替换为使用者选择的名称后安装：

```text
python ai_team.py install --grok-model 可用模型名
```

安装会保留 Python 启动器的路径，不主动解析到符号链接指向的版本目录。如果当前 Python 本身报告的是版本目录，可在 `install` 时用 `--python-cli "稳定的Python启动器路径"` 明确选择，工具会先做不联网的版本检查，再注册服务。不要选择会随升级删除的临时版本目录。省略该参数时仍使用当前解释器，不能保证它的路径长期不变。此设置只影响新安装，不会修改已有服务或运行中的任务。

本工具启动 Claude 客户端时会设置官方的安全模式环境变量，请求不加载所选配置中的 CLAUDE.md、技能、插件、钩子、MCP 服务和自动记忆；官方文档表示认证仍可正常使用。Windows 专用测试配置曾在设置这些变量后完成一次真实简短任务，见[验证记录](EVIDENCE.md)。这不是对实际加载内容的证明：旧版客户端可能忽略该变量，组织托管策略仍然生效。[环境变量说明](https://code.claude.com/docs/en/env-vars)

Claude Code 需支持 `--permission-prompts`（官方说明为 2.1.259 或更新版本）；使用前请先检查版本。官方还提示未来可能调整 `-p` 的默认启动模式，届时需重新验证已登录账号的兼容性。本机已核对 Grok 1.0.52 的实际帮助中包含本工具使用的命令参数，不代表其他版本已验证。[Claude CLI 参考](https://code.claude.com/docs/en/cli-reference) · [Claude 程序化运行](https://code.claude.com/docs/en/headless) · [Grok CLI 参考](https://docs.x.ai/build/cli/reference)

服务向主控暴露任务提交、状态和结果查询接口。主控负责理解任务、独立执行、向两家分工、核实结果并向用户说明不可用或未完成的部分。一家较慢或不可用时，另一家仍应能继续。提交是否成功无法确认时不自动重投。慢任务达到等待阈值后标记为未确认，后台可继续等待原进程并回收结果；服务重启后可以按原任务查询，但进程被系统终止或结果丢失时无法保证恢复。

新任务对 Claude 和 Grok 统一限制为 **100,000 个 UTF-8 字节**，并在保留请求或启动客户端前检查；中文字符通常占多个字节。超过限制时应缩短或拆分任务，再使用新的请求键，不能自动重发已有任务。旧版已接受的超长任务仍可按原请求键查询；用完全相同的原输入重放时只返回原记录，不重新提交。

如果某个任务的运行状态无法确认，它可能继续占用本工具的本地并发位置；此时主控应继续能够完成的部分，并说明缺少的协作。状态接口会分别显示近期有活动迹象的任务数和不确定的占用数；程序不会自动清理未知作业，可由使用者按下一节手动释放。

### 释放卡住的并发位

电脑重启或进程被终止后，未确认的任务会一直占用本地并发位，占满后该供应商只返回 `provider_busy`。先列出占位任务：

```text
python ai_team.py reconcile claude
python ai_team.py reconcile grok
```

由使用者本人确认对应的官方客户端进程已经退出后，再释放指定任务：

```text
python ai_team.py reconcile grok --release 任务编号 --confirm-process-exited
```

释放只修改本工具的本地记录：不结束任何进程，不向供应商取消，也不会重新发送。任务仍显示为提交状态不明，原因码为 `operator_released`；`release_basis=operator_confirmed` 是使用者的确认，不能当作程序观察到客户端退出。只有绑定的工作进程已被程序确认退出、且使用者另行确认该任务的官方客户端进程也已退出时，才能释放。AI 不得自行推测进程已退出或代替使用者添加确认参数；须由使用者对具体任务明确确认。尚未绑定身份、仍在运行、身份不可确认或记录破损的任务会被拒绝；旧版 Claude 任务可能没有身份记录，因此不能安全释放。释放前已有的部分结果尽力保留，释放后才返回的结果无法保证入账；使用者须自行核实该任务的所有相关进程。使用了自定义 `--data-dir` 时，这里也要带上相同的参数。账本应位于可信的私有目录；无法确认其安全性时不要使用释放命令。

如果启动阶段中断，记录可能尚未绑定可验证的工作进程，此时上述命令会拒绝释放。macOS 当前无法核实工作进程身份，也不能用该命令释放。主控应继续其他可完成的工作并说明限制，不要删除数据库、换任务标识重发或猜测进程状态。

#### 没有进程身份的旧任务

Windows 和 Linux 可使用 `legacy_reconcile.py` 对单个旧任务做分两步的人工对账。**只有使用者本人能够逐项确认下列条件时才能释放；AI 不得自行代为声明：**其他任务已经自然结束；旧调度器、旧 MCP 连接及其自动启动均已停用；账本仅在这台机器本地使用、未被其他设备共享；对应客户端进程已结束；已经安装新版且之后只有新版服务会访问账本，旧版不能再访问。若有任何一项不确定，就保留占位并调查。

先用上面的 `reconcile` 查看具体任务编号。将下面的 `<账本路径>`、`<任务编号>` 和 `<私有对账单路径>` 替换为实际值，在本目录运行：

```text
python legacy_reconcile.py prepare claude <账本路径> <任务编号> <私有对账单路径>
```

Grok 将 `claude` 改为 `grok`；Claude 账本位于数据目录的 `claude-jobs/jobs.sqlite3`，Grok 账本是 `grok-jobs.sqlite3`。对账单只供本机对账，保存到受操作系统保护的私有目录，不要提交或分享；Windows 上程序不验证目录权限。此步骤只读原任务并写入对账单。然后在确认其他任务均已结束且旧服务及自动启动已经停用后，由使用者**完整重新启动计算机**；休眠或快速启动关机不等同于重新启动。重启后不要启动旧服务。

只有重新逐项确认上述条件后，使用者才运行：

```text
python legacy_reconcile.py release <账本路径> <私有对账单路径> --attest-same-machine-local --attest-dispatchers-stopped --attest-full-restart --attest-cli-exited --attest-new-version-only
```

程序会检查账本文件和任务记录与快照是否一致。新对账单还要求：Linux 的系统启动标识改变；Windows 出现新的 `Kernel-General` 启动事件，原事件仍在系统日志中且内容一致。它不再要求重启后的开机时长更短，也不通过“当前时间减去开机时长”推算，所以单纯调快或调慢时钟不会放行。无法读取启动证据或原事件已清除时会拒绝，不降级到时钟判断。[Windows 启动事件说明](https://learn.microsoft.com/en-us/troubleshoot/windows-server/performance/troubleshoot-unexpected-reboots-system-event-logs)、[Linux 启动标识说明](https://docs.kernel.org/admin-guide/sysctl/kernel.html#random)。

旧的第 1 版对账单仍按原来的“运行时间下降”规则处理，保留其较短的操作窗口；不能事后补造启动证据。新第 2 版对账单须由新版工具处理。无论哪一版，以上都是本机辅助证据，不证明其他机器或远端任务已停止。五项声明仍由使用者负责，程序不能验证这些事实。释放后原任务保留为 `operator_released`、提交状态仍不明，不重发；已经保存的部分结果保留，之后迟到的结果可能无法入账。记录破损、仍有进程身份、账本变化、不可核验的路径或不受支持的平台会被拒绝。Windows 上已有一次合成账本的真实跨重启释放实测，范围见[验证记录](EVIDENCE.md)文末；真实供应商任务的跨重启释放仍未验收。不应为对账中断正在运行的任务。

拒绝时会显示固定 `Reason`，不输出异常原文或私有路径：`no_corroborating_restart` 表示未取得新的启动证据；`boot_evidence_unavailable` 表示系统记录无法读取或不完整；`ticket_mismatch` 表示对账单不适用；`job_has_a_worker_identity` 应改用普通 `reconcile` 并检查进程；`ledger_unreadable` 表示账本检查失败。先查明原因，不自动重发供应商请求，也不要删除数据库。

启动事件不验证完全重启、快速启动或休眠恢复的区别，也不证明客户端进程已经退出；不能代替使用者的五项确认。若日志轮转清除了对账单对应的原事件，该票会被拒绝，须在核对原任务后重新准备，并等待其他工作安全结束后由本人再次完整重启。不要自行删除旧票、重新派发或为这项测试中断其他工作。

如果提示“操作未确认”，包括写入或提交发生异常时，不要自动重试；先检查指定任务的账本状态和对账单。准备阶段写入失败也可能留下不完整的对账单。请在核对原任务后再人工决定如何处理。

如果本机账本尚未创建、不可访问或未通过安全检查，对账会返回失败并说明未检查到原任务；这不代表一定没有任务。

任务标识和请求标识也可能被记录、显示或传给供应商，不应包含个人信息或密钥；对账输出属于本机敏感记录，不应上传到公开仓库。

某一家没有启动时，状态接口的 `setup_issue` 会给出固定原因码：`cli_not_found`（找不到客户端）、`invalid_configuration`（模型、思考强度等参数不合法）、`local_state_unavailable`（本地目录或数据库不可用）或 `session_evidence_model_invalid`。原因码不含路径和错误原文。

## 状态与结果

| 状态 | 含义 | 后续操作 |
| --- | --- | --- |
| `not_submitted` | 本次尝试没有提交；仍须检查返回的原因与已有任务标识 | 不要据此猜测其他请求的状态 |
| `queued` / `running` | 工作已进入本地队列或正在处理 | 查询同一任务，不重复提交 |
| `submission_uncertain` | 无法确认提交或结果状态；可能仍在运行 | 继续查询原任务；不要换标识重发 |
| `succeeded` | 工具记录完整成功结果 | 检查回答及实际可核验的模型证据 |
| `incomplete` | 结果不完整，例如输出被截断 | 仅将可见部分当作部分内容，不当作完整答案 |
| `failed` | 本地记录明确失败 | 报告原因，不把失败或部分内容当成功 |

## 结果与隐私

任务文本会发送给所选供应商；只发送使用者允许分享的信息。运行产生的本机状态、客户端会话及供应商结果可能包含敏感内容，不要上传到公开仓库。Grok 的任务暂存在本机请求文件中；进程启动或删除失败时可能残留，不能保证自动清除。请确保本机数据目录仅对合适的账户开放；目录保护依赖操作系统权限。程序不内置作者的账号、登录状态、个人目录、历史任务、写作风格或个人模型偏好。

模型和思考强度只有在供应商返回可核验的证据时才可称为已验证；否则如实显示未验证。失败、退出和重启后可能存在未确认任务，不能凭空当作成功或自动重复提交。

新的完整成功 Grok 任务会尝试只读取本任务对应的官方客户端会话摘要和用量记录。记录安全、完整且与所请求的模型和强度一致时，结果显示 `client_record_verified: true`、观察到的模型和强度；这是**适配器报告的客户端本地记录核对结果**，协调器不独立认证记录来源，也不是服务端签名，`verified` 和 `server_effort_verified` 仍为 `false`。答案先保存，证据稍后可通过查询同一个任务获得；缺少记录、权限不安全、路径不受支持或记录不一致时，不会伪造验证结果，也不自动重发。该功能不主动删除会话：官方客户端可能保留提示词、回答、路径及其他文件，应使用私有专用配置。

`mismatch` 表示客户端记录中的模型或强度与请求不一致；一次会话可能包含其他内部调用，它本身不能证明最终回答使用了哪个模型。当前客户端记录检查支持安全条件满足的 Windows 和 Linux；macOS、同步目录中的链接、无法确认权限或过长工作路径可能显示未验证。会话、任务和结果可能保存在本机配置及状态目录中，不要上传这些目录。

Claude 的结果可能包含 `model_usage_matches_requested`：`true` 表示本次官方客户端成功结果中的模型用量汇总只有一个模型，且与请求的模型名称严格一致；`null` 或缺少该字段表示证据不足或无法判定，并不表示模型不匹配。模型使用别名、用量中包含多个模型，或官方记录里的规范模型名与请求名称不一致时，会保守地不判为匹配。这是客户端报告的用量记录，可能包含该次调用的内部模型调用，并非服务端签名，也不单独证明最终回答的实际模型或思考强度。缺少思考强度的可靠证据时，`effort_verified` 和总体 `verified` 保持为 `false`。旧结果不会补造证据。

登录状态和模型结果解析会拒绝有重复键的 JSON；无法判定的请求不会自动重发。结果保存在用户自己的私有状态目录，程序依赖该目录的访问权限，并未提供防篡改认证。客户端默认使用不持久化会话的模式，不能据此保证官方客户端或系统不产生其他本机记录。

Windows 使用者可明确选择 `--claude-session-evidence`，让新任务尝试核对该任务的官方客户端会话记录。**启用时官方客户端可能在本机暂存完整的任务、回答及路径，也可能创建其他记录。** 程序只尝试清理本次绑定的会话文件，不保证其他记录、备份或异常中断后的残留被清除；启用前请使用仅供本工具使用的私有配置和工作目录，确认其 Windows 权限合适。预检不能确认目录安全时，该任务会在启动模型前停止；旧任务不受开关变化影响。此功能不应通过共享配置绕过使用者的选择。

启用此模式时必须通过 `--claude-model` 明确指定客户端支持的完整 `claude-*` 模型 ID，不能使用 `sonnet` 等简写；程序不会根据别名猜测模型。ID 格式合格也不代表该模型可用于当前账号或实际执行已获验证。

例如，首次安装时可将 `--claude-session-evidence` 加到本节的 `install` 命令中。当前实现要求 Claude 配置中已经存在该工作目录对应的私有会话目录；如果返回 `session_evidence_unavailable`，表示本机预检未通过，并不表示任务已经发送或供应商发生错误。不要为解除限制修改其他任务的目录或权限；可先在不启用该选项的情况下使用本工具。安装标记仍会阻止重复安装，现有连接需按前文谨慎处理。

会话结果只表示客户端记录是否与请求的模型和强度一致，并非服务端签名或对服务端实际推理强度的独立证明。字段缺失、记录不完整或无法核对时显示未知，不会根据启动参数或回答内容补造证据。不同客户端版本可能改变其记录格式；清理只表示对绑定文件发起删除请求，不保证擦除所有副本。

答案已保存但会话证据仍在处理时，结果可直接读取，证据状态显示 `pending`。可继续查询同一个任务；不要再次发送。若后台进程中断，`pending` 可能长期无法确认，主控仍可继续其他工作。
